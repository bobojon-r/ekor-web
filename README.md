# eKor — мастер по вызову · web (Next.js)

Реализация дизайна из `../designs` на Next.js 15 (App Router) + TypeScript + CSS Modules.

```bash
npm install
npm run dev        # http://localhost:3000
npm run typecheck
```

## Бэкенд
Данные — с API https://lab.tcell.tj/api (`/api/docs`, WebSocket — `/api/ws-docs`). Источник выбирается при сборке:

| Переменная | Значение |
|---|---|
| `NEXT_PUBLIC_API` | `real` — бэкенд, `mock` (по умолчанию) — встроенные моки |
| `API_ORIGIN` | адрес бэкенда, по умолчанию `https://lab.tcell.tj` |
| `NEXT_PUBLIC_WS_URL` | WebSocket, по умолчанию `wss://lab.tcell.tj/api/ws` |

```bash
NEXT_PUBLIC_API=real npm run dev
NEXT_PUBLIC_API=real ./deploy.sh
```

- Браузер ходит на `/api` своего домена, Next проксирует в `API_ORIGIN` (rewrites) — CORS не нужен.
- Справочники (города, районы, категории) грузятся на сервере в `layout.tsx` (кэш 5 мин) и попадают в браузер вместе со страницей.
- `src/lib/api/http.ts` — Bearer-токены в localStorage, один общий refresh на 401; `realtime.ts` — WebSocket (сообщения, «печатает…», события заказа, уведомления, переподключение с перезапросом).
- `src/lib/api/remote.ts` и `real/*` — запросы и адаптеры ответов к типам экранов; моки остались рядом с теми же сигнатурами.
- Причины в модалках (отмена, отказ, спор, жалоба) идут в порядке справочника `/reasons` — индекс → `reason_id`.

## Вход по SMS: тестовый режим
SMS-шлюз пока не подключён. Вход — по номеру +992 и коду **123456**: на экранах есть плашка «Тестовый режим» и кнопка «Подставить 123456».
То же во всех местах с кодом: вход, создание задания, приглашение мастера, смена телефона.

С бэкендом код проверяет сервер (`/auth/otp/*`). Когда SMS-шлюз заработает: `NEXT_PUBLIC_SMS_ENABLED=true` — плашки «Тестовый режим» исчезнут.

## Структура
- `src/styles/tokens.css` — токены 1:1 из `../tokens.css`; `globals.css` — производные значения из макетов, брейкпоинт 1024px (`.mob-only` / `.desk-only`).
- `src/components/ui` — библиотека по дизайн-системе: Button (primary/secondary/danger/danger-outline/success, lg/md/sm/xs, busy «Отправляем…»), поля (TextField, TextArea, PhoneField +992 2-3-2-2, PriceField + «Договорная», OtpInput, SearchField), Chip, Segmented, LangSwitch, Switch/SwitchRow, Checkbox, RadioCard, StatusBadge (единый словарь статусов, подписи по роли), VerifiedBadge, Rating, Banner, Toast (2.4 с), Sheet/ConfirmSheet (шторка на мобильном, диалог на десктопе), EmptyState, Skeleton, Avatar, Card, Stepper.
- `src/components/layout` — SiteHeader 72px, AppBar 56px, TabBar 64px, SideNav 232px, Footer, Shell.
- `src/lib/i18n` — RU/TJ (cookie для SSR), плюрализация, форматтеры денег («до 1 500 смн», «Договорная»), «N мин назад», маска телефона.
- `src/lib/api` — фасад `api` и хранилища (задания, приглашения, отклики, кабинет и профиль мастера, чаты, уведомления): бэкенд или моки, см. «Бэкенд».
- `src/lib/hooks/useLoad` — правила загрузки: < 300 мс ничего, затем скелетон, 15 с «дольше обычного», 30 с «сервер не ответил».
- `src/lib/session` — сессия: с бэкендом — токены + `GET /me`, роль мастера по `is_master`; в моках — localStorage.
- `src/features/<экран>` — экраны: View + словарь + стили.

## Отклонения от handoff
- Шрифт самохостится через `@fontsource/golos-text`, а не грузится с Google Fonts: так он не зависит от доступности Google.
- `../backend/README.md` в поставке нет, поэтому контракт API пока выведен из данных в макетах.
